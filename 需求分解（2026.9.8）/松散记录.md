# 板块分割

注意 Labloom 比较高耦合。板块的分割不是完全清晰的。

1. Tab 系统：说是 Tab，其实是整个应用的浏览/路由系统，包括 Tab、Sidebar、前进后退等。
2. Feed：对标 Zotero 的 Feed 功能，一个 Feed 抓取器，用户管理 URL 和抓取频率，定时抓取新内容，并把新内容放到文献库的特定位置，摘要/标题等通知用户。
3. 文献库：对标 Zotero，可以查看和管理论文，查看就是一个 PDF Reader，但是需要实现笔记功能，笔记可以在选中文本上创建，也可以按坐标划定一个选区/点一个点创建，笔记内调用编辑器，就是一个页面。
4. 知识库：对标 Notion，一个富文本编辑器，可以创建页面，页面引用块，块可以有富文本内容。分为全局页面和非全局页面，非全局页面的引用计数为 0 自动进入回收站，全局页面只能手动删除进回收站。内置属性标签 `label`，用来 sidebar 默认分组，没有传统的底层文件夹结构。

# 板块要求

## 1. Tab 系统

Tab 系统管理“当前在看什么、怎么抵达、怎么返回”，各板块提供实际显示内容的组件。页面本身、页面的一次打开、一次浏览记录是三种不同的东西。

大致布局：

```text
┌─────────────────────────────────────────────────────────────┐
│ 侧边栏展开收起 后退 前进    标题1 Tab B Tab C   新建   -  □  ×  │  （Mac 左右按钮组对调）
├───────┬───────---─┬─────────────────────────────────────────┤
│ 搜索   │          │       Breadcrumb?  &  页面专用操作栏       │
│ 总览   │          ├──────────────────────────────────────--──┤
│ Feed  │           │                                         │
│ 知识库 │ 当前范围的 │                                         │
│ 文献库 │ 标签、收藏 │                                         │
│       │ 和筛选列表 │                                         │
│ [都是  │          │                                          │
│  图标] │          │   当前标签页目标对应的组件                  │
│       │          │   普通页面 / 论文阅读 / Feed / 设置 / ……    │
│       │          │                                          │
│       │          │                                         │
│       │          │                                         │
│ 回收站 │          │                                         │
│ 通知  │           │                                         │
│ 设置  │           │                                         │
└───────┴──────────┴─────────────────────────────────────────┘
```

1. 顶部 Tab 支持打开、激活、关闭、调整顺序；草稿暂定每个 Tab 各自维护前进后退记录。后退后访问新目标，截断该 Tab 原来的前进分支。
2. 普通点击在当前 Tab 导航，显式“在新标签页打开”创建新 Tab。切换已有 Tab 不新增浏览记录。需要恢复各目标的滚动位置、PDF 页码等视图状态。
3. Sidebar 的知识库 / 文献库入口切换查询范围，复用标签属性页面列表：知识库下，标签内出现普通页面和文献；文献库下，标签内只出现全局文献。
4. 标签属性内部有多个页面，一个页面也可以出现在多个标签属性下；这些条目是同一页面的多个入口。
5. Tab 标题和图标随目标更新；加载中、目标在回收站、目标不存在、打开失败都要有明确显示，不能留下空白区。
6. 离开或关闭正在编辑的页面前，要等待保存；保存失败时保留编辑内容并提供重试、返回处理的入口。
7. About / Overview 先保留路由与组件位置。Overview 的候选布局是近期页面、Feed 更新、任务和日程卡片；最终 UI 及任务日程的本轮范围待定。

## 3. 文献库与论文阅读

文献库提供文献查询、导入、属性展示、版本与附件管理、原文阅读及定位能力。它与知识库共享页面身份、标签和引用机制。

大致布局：

```text
文献列表：搜索 / 标签与属性筛选 / 导入
          标题 | 作者 | 年份 | 标签 | 附件状态

打开论文后：
┌─────────────────────────────────────────────────────────────┐
│ 标题    版本选择    属性开关    原文链接    页面操作            │
├──────────┬────────────────────────────┬─────────────────────┤
│ PDF 目录 │ 页码 / 缩放 / 文内搜索      │ 批注 / 阅读笔记     │
│ 或缩略图 ├────────────────────────────┤                     │
│          │ PDF 原文                   │ 批注列表            │
│          │ 高亮、区域框、点标记       │ 选中批注的页面编辑器│
└──────────┴────────────────────────────┴─────────────────────┘
```

1. 文献列表只查全局文献。非全局文献仍能从知识库或正文链接打开，不需要为了阅读而自动转成全局文献。
2. 论文始终使用同一个 `pageId`。书目信息是论文专属属性；个人标签和自定义属性沿用通用页面能力。来源书目信息与 PDF 原文只读，个人信息和笔记按各自权限编辑。
3. “文献库是只读子集”先理解为阅读原文和引用预览时不改写来源内容；导入、整理标签、写个人笔记仍提供操作。这个词是否还意味着整个入口进入纯阅读模式，需团队确认。
4. PDF Reader 暂按上文选用 pdf.js，提供翻页、跳页、缩放、适宽、文本搜索、选中文字，以及矩形区域 / 点定位；不在 Reader 内再实现一套富文本编辑器。
5. 批注正文是知识库页面，在右侧嵌入页面编辑器。点原文标记打开对应批注；点批注的来源入口回到对应版本和位置。整篇阅读笔记可以没有局部位置。
6. 文献未指定版本时打开最新版本；明确指定版本的引用、批注与阅读位置都绑定该版本。新增版本不得使旧批注自动漂移。
7. 文献详情同时显示该论文的相关笔记和使用记录，点击后交给统一导航打开。PDF 缺失或损坏时仍保留属性、笔记及可用的原文入口。
8. 导入至少考虑 Feed 和本地 PDF；DOI、BibTeX、版本比较、批注迁移等旧需求先列为后续交付项，排期时明确哪些包含在本轮。

# 板块之间的连接

## 1. 先共用哪些概念

以下是跨板块的数据约定，统一用 TypeScript 类型描述，并由数据层负责持久化；前端组件不要互相传数据库行或组件。

| 类型 / 概念 | 至少需要的信息 | 预期行为 |
| --- | --- | --- |
| `PageId`、`BlockId`、`TabId` | 各自稳定的标识 | 页面身份、块身份和一次打开相互独立，不用标题或数组下标作为身份 |
| `PageSummary` | `pageId`、页面种类、标题、`label`、全局状态、删除状态 | Sidebar、搜索、Tab 共用摘要；改名后各入口一致 |
| `Page` | 页面摘要、属性、有序的块使用关系、修订号 | 普通页面、论文、批注共用页面生命周期；各类型增加自己的属性 |
| `Block` / `BlockUse` | 块的 ID、类型、内容；使用位置的 ID、容器及顺序 | 内容按块身份共享；移除或移动一处使用只影响该位置 |
| `PageProperty` / `Label` | 属性名、类型、值、是否内置、是否可写；标签 ID 与显示名 | 属性显隐与读写权限分开；标签使用稳定 ID |
| `PaperVersion` | `pageId`、版本 ID、版本次序、书目信息、原文 URL、附件 | 版本属于论文页面；“最新”由数据层明确返回，不能靠版本字符串排序 |
| `ReferenceTarget` | 页面、块或原文位置的标识 | 展示形式变化时目标身份不变；原文局部目标固定文献版本 |
| `Reference` | 当前使用的 ID、目标、链接 / 同步模式、布局、只读 / 可写请求 | 展示参数属于当前位置；实际可写性还需检查目标 |
| `SourceAnchor` | 来源、版本 / 附件、页码、文字或几何位置、摘录 | PDF 定位使用文档坐标约定，不用屏幕像素；缩放后仍对应原位置 |
| `Annotation` | 批注 ID、正文 `pageId`、来源定位、标记样式 | 标记和正文有明确关联；正文由知识库管理，原文定位由 Reader 解释 |
| `FeedSource` / `FeedItem` | 来源配置与刷新状态；条目标识、正文 / 摘要、已读状态、关联文献及入库状态 | 抓取记录和文献记录分开，同一条目可以关联已存在的文献 |

块内容可以使用适合 Tiptap 的结构化数据，但需要保留外层稳定块身份，不能靠复制整段编辑器 JSON 来实现跨页面同步。具体序列化结构由知识库与数据层共同确定。

## 2. 所有“打开”共用一个目标类型

下面仅示意导航所需的信息；ID 的具体实现、查询条件类型和命名后续统一。

```ts
type OpenTarget =
    | { kind: "page"; pageId: PageId; versionId?: VersionId; blockId?: BlockId }
    | { kind: "source"; anchor: SourceAnchor }
    | { kind: "feed-item"; itemId: FeedItemId }
    | { kind: "collection"; scope: "knowledge" | "papers"; labelId?: LabelId }
    | { kind: "feed"; sourceId?: FeedSourceId }
    | { kind: "system"; name: "overview" | "about" | "settings" | "trash" };

type OpenOptions = { placement: "current-tab" | "new-tab" };

type open = (target: OpenTarget, options: OpenOptions) => {success: boolean, id: TabID};
```

`versionId` 只用于文献页面；`blockId` 必须是目标页面内可定位的块，入口收到不合法组合要返回明确错误。按页面 ID 打开时，先查询页面种类，再选择普通页面或论文组件，不要求调用者提前判断。打开原文定位时，Reader 准备好后再定位并突出显示目标。

Tab 保存 `OpenTarget`、历史和视图状态，不保存 Svelte 组件实例或业务正文。前端装配处把目标种类 / 页面种类映射到组件；组件类型只在前端使用，不穿过 IPC。

## 3. 每个板块需要交付什么

下列接口名表示能力边界，参数与返回字段要在接线前共同确定。跨 IPC 的调用统一异步返回；渲染组件的回调只报告意图或视图状态。

### Tab 系统提供

- 组件：`Tab`、`TitleBar`、`Sidebar`，以及加载、错误、目标已删除等通用占位视图。
- 类型：`OpenTarget`、`OpenOptions`、`TabState`、`ViewState`、`TabID`。`ViewState` 用于滚动位置、PDF 页码 / 缩放等，不包含正文。
- 接口：`open(target, options)`、`back()`、`forward()`、`switchToTab(tabId)`、`closeTab(tabId)`。
- 连接约定：Sidebar 条目、编辑器链接、Feed 通知、批注来源按钮都调用同一个 `open`。内容组件通过保存状态和离开前保存能力配合导航，Tab 系统不负责保存具体正文格式。

### 知识库提供

- 组件：`PageView({ pageId, mode })`、`PageEditor({ pageId, mode, showTitle, showProperties })`、`PageProperties({ pageId })`、`ReferenceView({ reference, onOpen })`、`PagePicker`。`mode` 为只读或编辑请求，仍受目标权限约束。
- 类型：通用页面、块、块使用关系、属性、标签、引用及保存状态。页面选择器返回稳定目标标识，不能返回一份复制的正文作为链接结果。
- 服务能力：`createPage`、`getPage`、`queryPages`、`updatePage`、`updateBlock`、`insertReference`、`removeReference`、`listBacklinks`、`setGlobal`、`trashPage`、`restorePage`。服务落地在统一数据层，知识库确定业务含义。
- 连接约定：论文右侧用 `PageEditor` 编辑批注；文献 Sidebar 用通用页面列表显示查询结果。`ReferenceView` 遇到原文目标时调用文献 / Feed 提供的预览能力，不能自行解析 PDF。
- 保存约定：组件暴露未保存 / 保存中 / 已保存 / 保存失败状态，以及异步的 `flush()` 能力，供切换和关闭前使用。修改同一块时使用修订号检查过期写入，冲突时保留当前编辑并提示处理。

### 文献库提供

- 组件：`PaperList({ query, onOpen })`、`PaperView({ pageId, versionId, anchor, onOpen })`、`PdfReader({ attachmentId, anchor, onSelection, onViewStateChange })`、`PaperProperties`、`AnnotationPanel`、`SourcePreview({ anchor })`。可选参数由调用场景省略。
- 类型：`PaperVersion`、`Attachment`、`SourceAnchor`、`Annotation`、`PaperImportInput`、`PaperImportResult`。导入结果至少区分新建、复用已有、新版本、待用户判断和失败，并给出可用的 `pageId` / `versionId`。
- 服务能力：`queryPapers`、`importPaper`、`getPaperVersion`、`listAttachments`、`listAnnotations`、`createAnnotation`、`updateAnnotationAnchor`。其中 `queryPapers` 固定筛选全局文献，按 ID 读取文献不受这个列表范围限制。
- 连接约定：Feed 提交来源元数据和来源标识，由 `importPaper` 决定复用或创建。知识库引用原文时使用 `SourcePreview`，打开完整原文仍交给 Tab 系统。
- Reader 的选区事件返回 `SourceAnchor` 和可用摘录，不创建正文。`createAnnotation` 将批注页面创建与来源关联一起提交，返回批注 ID 和正文 `pageId`，右侧直接挂载知识库编辑器。

### Feed 提供

- 组件：`FeedView`、`FeedSourceSettings`、`FeedItemView({ itemId, onOpen })`，以及需要被总览复用的更新摘要组件。
- 类型：`FeedSource`、`FeedItem`、`FetchStatus`、`FeedUpdateSummary`。
- 服务能力：`listSources`、`saveSource`、`removeSource`、`refreshSource`、`queryFeedItems`、`setReadState`、`retryImport`。定时刷新与手动刷新进入同一个流程，避免同一来源并发重复执行。
- 连接约定：抓取先保存条目，再调用文献导入能力，成功后记录关联 ID。以稳定来源条目标识使重试可重复执行，避免“文献已创建但 Feed 尚未记下关联”造成重复导入。
- 更新通知返回摘要和 `OpenTarget`，供应用外壳展示。通知、未读数与入库状态分别维护，阅读或移除通知不删除 Feed 条目或文献。
- 如果本轮包含 Feed 原文批注，Feed 还需提供自己的来源定位和预览能力，接入同一个批注正文编辑器；不能把网页位置冒充 PDF 页码坐标。

## 4. 后端与共享数据层

按上文，SQLite 与后端 API 由你负责。各板块先给出所需操作、参数、返回值和失败情况，再共同确定持久化结构。

```text
Tab / Sidebar / Feed / 文献组件 / 知识库组件
                    ↓
             统一的前端数据接口
                    ↓
               preload 暴露 API
                    ↓
       主进程业务服务：页面 / 文献 / Feed
                    ↓
          SQLite + 本地附件 + 网络抓取
```

1. 前端通过 preload 暴露的明确 API 操作数据；数据库、文件访问与定时抓取在后端完成。只通过 IPC 传可序列化数据，不传 DOM、Svelte 组件或 Tiptap 实例。
2. ID 分配、权限检查、引用计数、回收站级联、文献去重由数据层集中执行。把“创建非全局页面并插入引用”作为一次事务，避免页面尚未接入便因零引用被回收。
3. 批注同理：草稿建议来源到批注正文存在一条参与保留判断的有效关系；批注的反向来源属性只供定位，不反过来保留来源。该关系与普通引用如何统一存储，由数据层定；移除关联后仍被其他页面引用的批注继续保留。
4. 通用结果需要区分不存在、已删除、只读、输入无效、修订冲突、网络 / 文件 / 数据库失败。调用方根据失败类型提供入口，不解析随意拼接的错误文案。
5. 数据提交后发布变化通知，至少包含变化实体的 ID 与修订号。前端统一更新或失效对应缓存，使 Sidebar、Tab 标题、文献列表和同步内容一起刷新；组件卸载时取消订阅。
6. 共享数据接口还要能提供搜索、使用记录、阅读位置与耗时任务状态。具体界面可以后续补，但不要让各板块各存一份同名页面、标签或引用计数。

## 5. 用这些流程检查是否接得起来

1. **Feed → 文献 → Tab：** 新条目抓取后导入全局文献，添加指定标签；通知点击后打开返回的 `pageId`，Sidebar 能在对应标签下查到它；再次抓取或重试不生成重复文献。
2. **论文 → 批注 → 知识库：** 选中 PDF 文字，Reader 返回固定版本的定位；一次提交创建批注页面和来源关系；右侧嵌入 `PageEditor`。批注独立打开后，仍能回到原版本的选区。
3. **知识库 → 文献：** 在普通页面插入论文链接，通过 `ReferenceView` 显示标题 / 预览；点击统一导航打开论文。引用非全局文献不会使其出现在文献库列表。
4. **页面 A ↔ 页面 B 的同步块：** 两处使用同一 `blockId`，从任一可写位置编辑，另一处更新；移除 A 中的使用后，B 中的内容保留；随后直接删除目标时，剩余入口明确显示目标已删除。
5. **删除与保留：** 非全局文献最后一条有效引用移除后进入回收站，即使仍开着 Tab 也不阻止回收；恢复后 ID 和仍存在的共享块保持一致。全局文献不会因零引用自动回收。
6. **保存失败：** 页面保存失败时关闭 Tab，能返回编辑界面并保留输入；其他位置不能把未提交内容误报为已保存，重试成功后才统一刷新。

## 6. 开工前需要统一的细节

1. “文献库只读”的范围：仅来源正文 / 属性只读，还是从该入口打开时连个人笔记也默认只读？本草稿按前者安排布局。
2. Feed 中非论文资讯是否也创建全局页面，以及重复文献自动复用时是否追加订阅来源的标签；本草稿只明确论文自动入库。
3. 批注默认是否非全局、移除原文标记是否同时解除来源关联；需要明确按钮含义及保留关系，避免误删仍被使用的正文。
4. 原文定位格式：页码基数、坐标原点、旋转、归一化范围、多行选区、版本 / 附件身份；网页 Feed 原文另定定位格式。Reader、预览和存储必须采用同一套约定。
5. 本轮交付范围：Overview、任务日程、导入格式、版本比较、批注迁移、导出备份哪些本轮完成，哪些后续补齐。现有用户需求仍保留，不以这里的简略描述视为删除。

建议先接通“新建页面 → Tab 打开 → 保存”和“导入 PDF → 打开论文 → 创建并编辑批注 → 从批注返回原文”两条链路，再并入 Feed 和跨页面同步。这样每个板块交付时都有实际调用方可以验证。
