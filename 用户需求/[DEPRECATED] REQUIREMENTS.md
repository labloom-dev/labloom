## 1. 产品定位与边界结论

Labloom 是面向学生个人的、个性化的、一体化的 AI 科研工作台。它把论文与资讯收集、阅读笔记、论文草稿、任务和截止日期管理连接起来，帮助学生从获取资料走到完成自己的研究任务。

建议用以下工作流界定首版：

**发现论文和行业资讯 → 收入论文库或项目 → 阅读并记录笔记 → 组织论文草稿 → 跟进任务与 DDL。**

AI 在上述工作流中辅助筛选、理解、整理和写作；个人关注方向、项目和截止日期决定工作台展示的内容。首版以一名学生独立完成这条工作流为交付目标。

| 范围层级 | 本次结论 |
| --- | --- |
| 已明确的产品方向 | 学生科研工作台；个性化、一体化、AI；基础论文功能、论文草稿、行业新闻、DDL 管家 |
| 已明确的项目约束 | 一个学期项目；团队决定使用 Labloom 作为名称 |
| 建议首版 | 个人工作区、基础论文库、阅读与笔记、项目与草稿、论文及行业资讯、任务与 DDL、Today 总览、嵌入流程的 AI 辅助、必要的来源与服务配置 |
| 扩展候选 | 专门的课程模块、Zotero/Notion/日历同步、Agent 模板与独立运行中心、更多来源和跨设备同步 |
| 暂不纳入首版 | 集群与 GPU 作业管理、开放插件市场、多人协作、完整文献软件替代、完整学术排版与投稿平台 |

“包含 Zotero 的基础论文功能”说明 Labloom 本身需要论文管理能力；是否接入 Zotero 是另一项集成决策。仅跳转到 Zotero，不能满足首版论文库的目标。

## 3. 用户与核心场景

首版主要用户是一名同时处理课程任务与科研工作的学生；不预设必须是本科生、研究生或某一研究领域。

| 场景 | 用户希望完成的事 |
| --- | --- |
| 开始一天 | 在一处看见近期 DDL、待办、当前项目和关注领域的新内容 |
| 收集资料 | 保存论文、附件和行业资讯，按项目或主题组织并再次找到 |
| 阅读理解 | 查看论文，记录笔记，获得有资料依据的 AI 辅助 |
| 推进写作 | 把资料和笔记组织成可继续编辑的论文草稿，并保留引用来源 |
| 跟进截止日期 | 记录任务、安排截止时间与提醒，在完成后更新状态 |

课程作业的截止日期可以进入首版任务管理；这不要求同时建设课程门户或连接学校教务系统。

## 4. 建议首版功能范围（P0）

P0 表示建议在学期交付中完成的最小行为。以下拆分均为本次细化，原始资料没有逐项规定其操作、格式或验收标准。

### R-01 个人工作区与个性化

- 保存个人关注的研究方向或关键词、项目分类和提醒偏好。
- 这些设置实际影响资讯筛选和 DDL 展示，不能只停留在姓名、头像或主题设置。
- 以单用户工作区为首版假设；账户体系和登录方式随部署方案确定。

验收：设置一组关注关键词后，资讯列表能按其筛选；重新打开工作台后设置仍然存在。

依据：C-01；S2 的个人 workspace、Settings。

### R-02 基础论文库

- 新建、查看、编辑和移除论文条目，记录标题、作者、年份、摘要、来源链接和标识符等基础元数据；不要求每个字段必填。
- 关联 PDF 附件或原文链接；支持按项目、集合或标签组织，以及按标题、作者、关键词查找。
- 提供基础文献交换能力，建议首版采用 BibTeX 导入与导出；自动通过 DOI 抓取元数据作为增强项。
- 给缺失元数据、无法读取的附件和导入失败提供明确反馈；疑似重复条目允许用户处理，不做静默覆盖。

验收：导入或录入论文，关联附件，归入某个项目，搜索后重新找到它，并导出其引用信息。

依据：C-02；S2 的 Paper Library。上述“基础”的具体边界为本次建议，不等同于承诺完整复刻 Zotero。

### R-03 论文阅读与笔记

- 能打开关联的论文 PDF 或原文链接，并创建、保存和编辑与该论文关联的阅读笔记。
- 笔记可以归入项目，在查看笔记时返回相应论文。
- AI 阅读结果可由用户选择保存到笔记；引用或摘录保留可回查的来源。
- 首版不要求自研完整 PDF 阅读器，也不要求页内高亮批注、扫描件 OCR 或手写识别。

验收：从论文库打开资料、写一条笔记，再从笔记回到原论文；重新打开工作台后关联关系仍在。

依据：C-02 的细化；S2 的 Projects & Notes；A2/A3 的阅读工作流仅作辅助解释。

### R-04 项目、笔记与论文草稿

- 创建项目，将相关论文、笔记、草稿和任务放在同一项目中查看。
- 创建、编辑、保存并重新打开论文草稿，支持标题和基本章节结构。
- 草稿能关联所用论文，提供基础引用清单；建议首版支持正文文本或 Markdown 导出，并通过 R-02 导出引用信息。
- AI 可辅助形成提纲或修改选定内容，由用户决定是否采纳；不直接覆盖用户草稿。
- 首版不承诺 Word/LaTeX 双向兼容、完整引用样式系统、期刊模板和投稿流程。

验收：基于同一项目的论文与笔记建立草稿，加入至少一条可追溯引用，保存后继续编辑并导出。

依据：C-03；S2 的 Projects & Notes。

### R-05 论文动态与行业资讯

- 保存关注方向和订阅来源，汇总新论文与行业新闻，显示标题、来源、发布时间（来源提供时）和原文链接。
- 支持筛选、已读或收藏状态；感兴趣的论文可进入论文库，资讯可收藏到项目。
- 首版至少接通一种论文来源和一种行业资讯来源，具体来源待选；arXiv 是截图提供的论文来源候选。
- 支持用户主动刷新，并展示最后刷新时间、结果和失败原因；自动刷新频率另行确定。
- AI 可基于实际取得的标题、摘要或正文做摘要和相关性说明，需说明使用了哪类材料。
- 行业新闻不能只用论文更新替代；不把全网抓取、付费内容全文获取或复杂推荐系统列为首版承诺。

验收：刷新已配置来源后看见符合关注方向的论文和行业资讯，打开原始来源，并分别保存到论文库或项目；来源不可用时不显示虚假更新成功。

依据：C-04、C-01；S2 的 arXiv Radar。新论文与行业资讯的具体聚合方式为本次细化。

### R-06 任务与 DDL 管家

- 创建、编辑和完成任务，保存名称、截止日期或时间、状态、优先级及提醒设置，并可关联项目或课程标签。
- 显示即将到期、已逾期和已完成任务；区分只有日期的 DDL 与精确到时刻的 DDL。
- 首版至少提供应用内到期提示和提醒列表。系统通知、邮件、移动推送，以及应用关闭后的提醒能力，随目标平台另行确定。
- 支持手工录入以完成核心流程；自动从邮件、课程平台或文档抽取 DDL 作为后续增强。

验收：创建带截止时间和提前提醒的任务，在设定时区下正确显示到期状态；完成任务后不再作为未完成事项提醒。应用内提醒的触发条件应明确可见。

依据：C-05；S2 的 Tasks、Today 和日历集成示例。

### R-07 Today 总览与统一查找

- 聚合近期截止日期、待办、当前项目和关注领域的新内容，并能直接进入对应条目。
- 提供至少覆盖论文、项目、笔记和任务标题的统一查找入口。
- 总览复用各模块的同一份条目和状态；从总览完成任务或收藏论文后，相关模块同步反映变化。

验收：从 Today 找到即将到期任务并完成它，任务列表显示一致状态；能从查找结果打开已有论文或笔记。

依据：C-01 的“一体化”；S2 的 Today、Quick search。

### R-08 嵌入工作流的 AI 辅助

- 首版建议覆盖论文或笔记摘要、草稿提纲或改写、资讯相关性解释三类小任务。
- 运行前明确使用的资料范围；结果保留原始材料或来源入口，不能把只有摘要的输入呈现成已经通读全文。
- 展示运行中、成功和失败状态；保留任务输入范围、结果及必要的运行记录，支持重新发起。
- 保存到笔记、加入草稿等动作由用户选择；AI 不可用时，论文、笔记、草稿和任务的手工操作仍可使用。
- 至少接通一个实际可用的模型服务完成演示；供应商、模型、接入方式和费用额度待定。截图中的 Codex Runner 不构成指定技术依赖。
- 首版可用固定任务入口和简单结果记录满足需求，不要求通用 Agent 编排、任意代码执行或独立 Agent 管理平台。

验收：选择一篇有可用文本的论文或笔记，获得有来源说明的摘要并选择保存；一次 AI 调用失败后原资料、笔记和草稿保持完整。

依据：C-01；S2 的 Codex Runner、Agent Runs、Agent Templates。具体 AI 任务及边界为本次建议。

### R-09 必要的来源与服务配置

- 为首版实际采用的论文来源、资讯来源和 AI 服务提供配置入口。
- 显示用途、读取或写入方向、配置或启用状态、最后操作结果；适用时提供连接测试、手动刷新和重试。
- 未配置或连接失败的服务应如实展示；不能把参考截图中的“已启用”和统计数量写成固定成功状态。
- 各类服务有清楚的职责边界，便于以后替换；首版不要求开放插件安装或插件市场。

验收：配置或停用一个来源，工作台行为随之改变；错误配置能被识别并提示修正，已有本地或已保存资料仍可访问。

依据：S2 的 Integrations。统一配置是为首版实际依赖服务补出的支撑范围。

## 5. 首版数据关联与质量要求

以下是支持核心流程的最低关系要求，不指定数据库、接口协议或类结构：

| 对象 | 必须保留的关系或信息 |
| --- | --- |
| 论文 | 元数据、附件或链接、所属项目或分类 |
| 笔记 | 对应论文或资料来源、所属项目 |
| 草稿 | 所属项目、使用的论文或引用清单 |
| 资讯 | 来源、原文链接、发布时间（如有）、收藏状态及关联项目 |
| 任务 | 所属项目或课程标签（可选）、截止日期或时刻、提醒和完成状态 |
| AI 结果 | 任务类型、使用的材料范围、来源和运行状态 |

建议首版同时满足：

- 保存的数据和关联关系在重启后仍可恢复；提供基本导出路径，使用户能带走自己的论文信息、笔记、草稿与任务数据。
- 已保存资料与手工操作不依赖 AI 服务成功；资讯刷新或模型调用失败不能清空既有数据。
- 明确实际使用的数据存储位置及哪些材料会交给外部服务处理；服务凭据不进入导出内容或普通运行记录。
- 对空列表、缺失字段、无法打开的附件、超时和失败给出可理解的状态。
- DDL 的时区、只有日期的截止日解释及提醒触发条件保持一致。
- 论文和资讯能回到原始来源，AI 结果与用户撰写内容可区分。

上述要求是本次建议，不意味着已经确定本地优先、云托管、完全离线或端到端加密方案。性能、容量、操作系统兼容范围待目标平台和演示规模明确后制定。

## 6. 扩展候选（P1，完成 P0 后再选择）

| 候选 | 可增加的能力 | 首版边界或前置条件 |
| --- | --- | --- |
| Courses | 课程、作业、公告与 DDL 汇总 | 先确定目标学校和可用数据；UT Canvas 只是一种示例 |
| Zotero 集成 | 与既有文献库交换或同步条目、附件 | 先完成独立论文库；确定同步方向、映射与冲突处理 |
| Notion 集成 | 导出或同步项目笔记 | 先确定单向导出是否足够及哪些内容需要同步 |
| 日历集成 | 读取已有日程、导出任务截止日期 | Apple Calendar 不是指定平台；需先确定用户环境和同步方向 |
| Agent Templates / Agent Runs | 可复用任务模板、独立历史页、定时执行 | 先完成 R-08 的固定任务与结果记录 |
| 文献与阅读增强 | DOI 自动补全、浏览器采集、全文索引、页内批注、OCR | 按最常见资料类型选择，不能阻塞基础录入和阅读 |
| 写作增强 | 更多导出格式、引用样式和版本历史 | 先完成基础草稿及引用关联 |
| 自动资讯与 DDL | 定时更新、更多新闻源、自动抽取截止日期、系统通知 | 依赖来源、后台运行方式和通知环境 |
| 数据同步 | 多设备、更多备份恢复方式 | 先明确本地与服务端的职责及冲突规则 |

这些候选仍需按团队人数、剩余时间和演示价值选择，不能因出现在截图或聊天助手回复中就默认全部交付。

## 7. 暂不纳入本学期首版的内容

以下是控制学期交付规模的建议排除项，原对话没有直接否决它们：

- TACC Vista、Cluster、Slurm、GPU 训练提交、远程文件和资源监控。

## 8. 首版整体交付判定

首版应能使用真实录入或导入的数据走通以下演示，而不只是展示独立的静态页面：

1. 设置关注方向，刷新论文与行业资讯，将一篇论文收入库中，将一条资讯收藏到项目。
2. 打开论文并记录笔记，在同一项目下建立草稿并关联引用。
3. 对选定材料执行 AI 摘要或草稿辅助，检查来源后选择保存结果。
4. 为项目建立 DDL 和提醒，在 Today 查看并完成任务。
5. 重新打开工作台，确认资料、笔记、草稿、任务和关联关系仍然存在，并导出用户数据。
6. 演示一次来源连接失败或 AI 调用失败，能看见失败原因并继续手工工作。

每项具体行为以 R-01 至 R-09 的验收描述为准。参考服务未接入时可以展示未配置状态，但不能用模拟成功数据代替上述核心链路的验收。

这些事项不影响当前产品方向判断，但会影响方案、工作量与验收环境：

| 待定项 | 当前能确定的内容 | 需要决定的内容 |
